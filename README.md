# molt-sign

A standalone Node.js command-line tool for signing and verifying exact byte sequences with Ed25519. It uses Node's built-in `node:crypto` only; there are no dependencies, build steps, network calls, key generation, or ledger operations in the tool. It supports Node.js 22 and 24.

## Run

No installation is needed. From this folder:

```sh
node molt-sign.mjs sign --key identity.json --in canonical.bin
node molt-sign.mjs sign --key identity.json < canonical.bin
node molt-sign.mjs verify --pub PUBHEX --in canonical.bin --sig SIGHEX
node molt-sign.mjs verify --pub PUBHEX --sig SIGHEX < canonical.bin
```

`sign` prints one 128-character lowercase hexadecimal signature and a newline. `verify` prints `PASS` and exits 0 for a valid signature, or prints `FAIL` and exits 1 for an invalid signature. Malformed arguments, key files, hex, files, or signature lengths produce an error on stderr, a non-zero exit code, and no stdout. Input bytes are signed as-is; the tool does not pre-hash, canonicalize, add, or remove bytes. Signing reads a private seed but never prints or writes it.

## Identity files

The `--key` file accepts either format:

1. MOLT manifest signer: a JSON object whose only top-level property is `manifest-signer`, containing `priv` and `pub` as 64-character lowercase hex values (32-byte Ed25519 seed and public key).

   ```json
   {"manifest-signer":{"priv":"<64 lowercase hex characters>","pub":"<64 lowercase hex characters>"}}
   ```

2. `molt.ed25519-identity.v1`: a JSON object with `schema` set to `molt.ed25519-identity.v1`, `algorithm` set to `Ed25519`, a non-empty `purpose`, `privateKeyHex`, `publicKeyHex`, and `keyId`. The key ID must be the lowercase SHA-256 hex digest of the raw public-key bytes. The tool checks that the private seed derives to the stated public key and rejects a mismatched identity.

Neither form is generated by this tool. The tool does not write keys or identity files.

## Pairing with molt-canonical

`molt-canonical` returns a canonical JSON string and its hash; the displayed output includes an extra hash line and newline, so do not sign that whole display output. Save the canonical string itself, without an added newline, then sign those exact bytes. For example, with both tools available in the current directory:

```sh
node --input-type=module -e 'import { readFile, writeFile } from "node:fs/promises"; import { canonicalizeJsonText } from "./molt-canonical.mjs"; const input = await readFile(process.argv[1], "utf8"); await writeFile(process.argv[2], canonicalizeJsonText(input), "utf8");' manifest.json canonical.bin
node molt-sign.mjs sign --key identity.json --in canonical.bin > signature.hex
```

Anyone with the corresponding 64-character public key can verify the canonical bytes with `molt-sign verify`; the verifier does not need the private identity file.

## Tests

Run the built-in Node.js test suite:

```sh
node --test
```

Or run the package script:

```sh
npm test
```

The tests generate fresh ephemeral key pairs and temporary identity files. The RFC 8032 empty-message vector is included as a published test vector, not as a deployed key.
